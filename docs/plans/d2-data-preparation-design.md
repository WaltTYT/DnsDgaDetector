# D2 数据准备设计

> 状态：评审通过
> 日期：2026-11-01
> 范围：阶段 1 的 D2；D3 DNS 查询日志生成另行设计。

## 1. 目标

D2 建立可追溯、可复现的正常域名与 DGA 域名集合，生成手工 DGA 样本，并按可注册域名分组划分训练集、验证集和测试集。D2 的结果供 D3 日志生成、D5 基线拟合及后续评估使用。

D2 不下载或执行恶意软件，不对域名发起 DNS 查询，不生成查询日志，不拟合检测阈值，也不使用 LLM 判断数据标签。

## 2. 设计编写时的仓库状态

以下条目记录 2026-11-01 设计初稿时的状态，不代表当前实现状态：

- `data/sources.md` 当时仍是待填写模板。
- `data/normal_domains.txt` 当时为空；`data/dga_domains.csv`、`data/splits.csv` 和 `data/dns_log.csv` 当时只有表头。
- `src/prepare_data.py` 和 `src/gen_dga.py` 当时只有职责与待实现要点；后续实现应保留本设计的行为契约。
- 五类共享数据产物的列名和顺序以 [数据契约 v1](data-contracts.md) 为准。本设计不增加或改动表头，但提出一项 `algorithm` 空值语义澄清，须在 D2 生成共享数据前同步到契约文档。

D2 的实际输入、计数、哈希及当前数据限制记录在 [`data/sources.md`](../../data/sources.md)；实现入口为 `python -m src.prepare_data`。

## 3. 数据组成与规模

| 类别 | 目标规模 | 标签与说明 |
|---|---:|---|
| 公开正常域名 | 约 3,000 个 | `label=0`；公开榜单只作为良性近似，不宣称所有域名均安全 |
| 难负样本 | 约 100 个，额外加入正常集合 | `label=0`；覆盖 CDN/云平台哈希子域、含数字的合法域名等；每条记录要有可核查的来源依据 |
| 公开 DGA 域名 | 从一个来源可核验、带标签的公开数据集中按家族分层选取，目标约 300 个 | `label=1`；保留原数据集的家族标签与来源标识 |
| 手工 DGA 域名 | 300 个，每种算法 100 个 | `label=1`；只表示由本项目生成算法产生，不代表现实恶意 |

公开 DGA 的约 300 条是本设计为控制数据规模提出的目标，不是路线图规定的硬指标。实际可用数量、去重数量和排除数量须如实记录。公开 DGA 数据不足目标量时使用全部合格样本；超过目标量时按家族分层、固定种子抽样。若来源没有可解释的家族标签或许可条件不清，不能为了达到数量而纳入。

## 4. 来源核验与原始输入

### 4.1 来源选择

- **正常域名候选**：优先核验 Majestic Million；如下载或许可条件不适合课程项目，可使用具有明确来源、版本和许可说明的替代公开榜单，并记录替换理由。
- **公开 DGA 候选**：优先核验 `360netlab/DGA`。实施前确认具体文件、数据版本、家族标签含义、许可和下载方式；不能把仓库名当成数据来源证明。
- **PSL**：使用 Public Suffix List 官方发布的固定快照，记录获取日期、文件 SHA-256 和许可信息。是否包含 PRIVATE 区由本设计固定为包含。
- **难负样本**：每条样本记录稳定来源 ID、可核查的 URL 或公开文档、选择理由及其合法性依据；不能只凭域名“看起来正常”标注。

上述公开来源均为候选来源，不表示已经下载或完成许可审核。`data/sources.md` 是最终来源清单，至少记录名称、URL、版本/获取日期、许可、标签语义、原始文件名及 SHA-256、纳入规则、原始/有效/排除数量。无法再分发的原始文件不提交仓库；改为记录获取说明和哈希。

### 4.2 原始输入与离线重放

获准使用的原始快照放在 `data/raw/` 下，并按来源 ID 命名，避免不同来源的同名文件互相覆盖。域名清单按来源分别保存，例如 `normal_list__<source_id>.txt`、`hard_negative__<source_id>.txt` 和 `public_dga__<source_id>.<ext>`；`data/sources.md` 将来源 ID 映射到具体文件、来源类别和可核验出处。这样即使共享 CSV 按契约归并 `source` 枚举，仍可用原始快照追溯来源。下载和来源核验是显式的数据准备步骤；`prepare_data.py` 与 `gen_dga.py` 的生成过程只读取本地输入，不在运行时联网。

所有原始输入保持只读。规范化、去重、排除和划分结果写到契约规定的输出文件；不得把源文件直接改写成规范化结果。来源文件哈希和固定种子共同构成重现该次 D2 数据版本的依据。

## 5. 域名规范化与冲突处理

对每个源文件使用相同规范化流程：

1. 去除记录两端空白；只接受域名字段，不从 URL、路径或任意文本中猜测提取域名。
2. 去掉末尾根点，按固定 Python/IDNA 规则转换为小写 ASCII 域名。
3. 校验标签非空、每个标签长度为 1–63 字符、域名长度不超过 253 个 ASCII 字符；拒绝 IP 字面量、通配符、空值和格式非法记录，并计入排除统计。
4. 用随 D2 固定并记录 SHA-256 的本地 PSL 解析可注册域名；训练/验证/测试分组与后续特征模块共享同一 PSL 快照，启用 PRIVATE 区。

通过语法规范化但在固定 PSL 下无法得到 eTLD+1 的记录（包括公共后缀本身及 PSL 未收录的后缀）不参与抽样和划分。流水线将其作为显式排除项，保留 source ID、相对路径、原始行号、原始域名和原因，并计入来源 `excluded` 数；CLI JSON 摘要输出逐条明细。`assign_splits` 对直接传入的无 eTLD+1 记录仍立即报错，避免未筛选记录进入分组算法。

同一个规范化 FQDN 重复出现时按以下规则处理：

- 同标签、同算法语义的完全重复项合并，保留来源计数。
- 同一 FQDN 同时被标为正常和 DGA 时，视为标签冲突并停止发布划分结果；必须查明源数据标签含义后人工解决，不得按来源优先级静默覆盖。
- 同一 DGA FQDN 对应多个不同家族/算法时，视为算法元数据冲突并停止；来源原始记录保留以便审查。
- 手工生成样本与现有域名集合发生碰撞时，生成器使用确定性的下一个候选 seed 重试，并把最终 seed 与必要参数写入 CSV；不得静默丢弃碰撞后仍声称生成了 300 个样本。

共享产物严格使用数据契约 v1 的枚举：正常榜单与难负样本统一写 `source=normal_list`、`algorithm` 留空；公开 DGA 写 `source=public_dga`、`algorithm` 留空；手工样本写 `source=manual_dga`、`algorithm` 使用本设计第 6 节的固定枚举。具体榜单、数据集、家族和难负样本出处用 `data/sources.md` 的来源 ID 与按来源保存的原始输入追溯，不得把自定义来源 ID 或公开家族名写入契约枚举列。

公开 DGA 原文件中的家族字段保留在只读原始快照中；契约 v1 没有逐域名家族列，因此共享 `splits.csv` 只用 `source=public_dga` 区分公开 DGA，不承诺按公开家族计算独立指标。若项目后续需要逐域名家族分析，应另行评审并升级数据契约，D2 不私自扩展字段。

**契约语义澄清建议**：v1 当前把空 `algorithm` 写为“正常样本”，但公开 DGA 不适用本项目三种手工算法。D2 实施前应把该描述澄清为“未应用项目手工生成算法”；样本类别由 `label` 与 `source` 共同确定。该修改不增加字段或改变表头，但必须同步更新 `docs/plans/data-contracts.md`，再生成 `splits.csv`。

## 6. 手工 DGA 生成

`gen_dga.py` 生成 300 个唯一的完整域名，每种算法各 100 个，统一使用 `.com` 后缀以减少后缀变量。算法只生成教学用字符串，不执行网络操作，也不模拟某个具体恶意软件家族。

| 算法 ID | 生成逻辑 | 参数与复现要求 |
|---|---|---|
| `rand_alpha` | 使用小写英文字母生成 12–18 字符标签 | 每条样本使用独立、可追溯的字符串 seed；`params` 记录标签长度和后缀 |
| `word_digit` | 从 `data/raw/manual_word_roots.txt` 中的项目自有固定词根表选取 1–2 个词根拼接，再附加 2–4 位数字 | 固定词根表及其 SHA-256；`params` 记录词根表版本/哈希、选词数量、数字位数和后缀 |
| `md5_date` | 将 `YYYYMMDD|<sample_seed>` 编码为 UTF-8 后计算 MD5，取十六进制摘要前 12–16 位作为标签 | `params` 记录日期、截断长度和后缀；MD5 仅作确定性教学模拟，不用于安全用途 |

主种子固定为整数 `20261101`，写入 `config.json.seed`。每条样本 seed 使用 UTF-8 字符串 `<master_seed>:<algorithm>:<index>`，其中 `<index>` 固定为 4 位十进制并从 `0001` 开始；随机算法使用该 seed 初始化 Python 3.11.17 的独立 `random.Random` 实例。词根从按文件行序读取的词表中确定性抽取。MD5 日期取固定 `2026-11-01`，拼接前移除日期中的连字符，输入格式严格为 `YYYYMMDD|<sample_seed>`。同一 `algorithm + seed + params` 必须能重建完全相同的域名。词根表和 PSL 的内容变化均视为输入版本变化，必须更新相应哈希与数据来源记录。

输出严格遵循契约 `data/dga_domains.csv`：`domain,algorithm,seed,params`。`params` 为合法 JSON 对象字符串；相同内容使用稳定序列化方式输出。CLI JSON 摘要按算法提供 `count`、`unique_count`、`collision_retries` 和 `example_domains`；示例固定为成功样本 index 最小的前三个域名（不足三个时全部列出），并保留全局 `collision_retries` 汇总。

## 7. 划分策略

划分输入是规范化并去重后的正常域名、公开 DGA 域名和手工 DGA 域名的合并池。先检查同 FQDN 标签/算法冲突，按固定 PSL 筛出可提取 eTLD+1 的来源记录，并将不符合项列为有来源明细的排除记录；无法按固定 PSL 提取 eTLD+1 的记录不得进入划分。直接调用 `assign_splits` 时仍对这类记录报错。

以 eTLD+1 作为不可拆分的 group，确保某注册域及其子域只属于一个 split。目标比例按域名条数近似为 train/val/test = 60/20/20。令 `N` 为域名总数，`N_c` 为分层 `(label, source, algorithm)` 中类别 `c` 的域名数，`r_s` 为 split `s` 的目标比例，`n_s` 和 `n_{s,c}` 为当前已分配到 split 的总域名数及类别 `c` 数。候选分配的损失为：

`L = Σ_s [((n_s - r_s*N) / max(1, r_s*N))² + Σ_c ((n_{s,c} - r_s*N_c) / max(1, r_s*N_c))²]`

采用不依赖运行时哈希随机化的确定性贪心分组分层：

1. 按每个 eTLD+1 group 的域名数量及 `(label, source, algorithm)` 计数构建分层统计。
2. 按 group 大小降序处理；同大小使用 `SHA-256(str(master_seed) + "|" + eTLD+1)` 的小写十六进制摘要升序打破平局。
3. 对每个候选 split 临时加入当前 group，计算上述 `L`，选择总损失最低的 split；并列时按固定顺序 `train`、`val`、`test` 选择。
4. 分配后验证比例、三种手工算法在每个 split 的覆盖和 eTLD+1 无交集；若约束无法同时满足则失败并报告差异，不拆分 group 或静默改 seed。

比例是近似目标；如果大 group 使 60/20/20 无法精确满足，应优先保证 group 不泄漏，并报告实际域名数和比例。每次输出都记录主种子、PSL 哈希、输入文件哈希和各 split 的样本统计。测试集只作为最终评估集合，不用于后续阈值选择或提示调优。

## 8. D2 产物与边界

| 产物 | D2 责任 | 格式/约束 |
|---|---|---|
| `data/sources.md` | 填写来源、许可、标签说明、版本、哈希、纳入统计 | 来源可核验；不得宣称未验证的下载或许可状态 |
| `data/raw/` | 保存允许再分发的只读来源快照和固定 PSL | 不可再分发的材料不入库，保留获取说明与哈希 |
| `data/normal_domains.txt` | 输出正常榜单与难负样本合并后的域名池 | UTF-8，每行一个规范化唯一 FQDN，无表头，稳定排序 |
| `data/dga_domains.csv` | 输出手工生成域名及可重现参数 | 严格遵循五类数据契约 v1 的固定表头与字段语义 |
| `data/splits.csv` | 输出正常、公开 DGA 和手工 DGA 的唯一域名标签及固定划分 | 严格遵循契约 v1；每个规范化 FQDN 仅一行 |

D2 不填充 `data/dns_log.csv`；日志生成属于 D3。新增的原始来源文件只是生成输入，不增加或替代五类共享数据产物。

## 9. 验收与测试

D2 完成前至少通过以下检查：

- 来源、许可、标签语义、版本/获取日期与 SHA-256 齐全；原始数据是否可提交有明确结论。
- 正常公开域名约 3,000 条，难负样本约 100 条且逐条有依据；实际数量与排除原因可复核。
- 手工 DGA 共 300 条，每种算法各 100 条；输出唯一，重复运行完全一致，单行 seed/params 能重建该域名。
- 规范化测试覆盖大小写、尾随根点、IDNA、非法标签、IP、通配符、重复域名和标签/算法冲突。
- `splits.csv` 表头与 v1 完全一致；域名无重复、标签无冲突；任一 eTLD+1 不跨 split；划分比例及各手工算法覆盖满足本设计，或以失败报告阻止交付。
- 在删除生成输出后重跑数据准备流程，文件内容与哈希完全一致；执行过程不访问网络。
- `data/dns_log.csv` 仍由 D3 负责生成；不得把域名列表包装成真实 DNS 查询日志。

建议新增的单元测试分别覆盖 `gen_dga.py` 的确定性/算法数量/参数重建，以及 `prepare_data.py` 的规范化/冲突处理/分组无泄漏/固定划分。测试使用临时目录和小型 fixture，不依赖公开数据下载或外部 DNS。

## 10. D3 衔接

D3 读取 `data/splits.csv`，按各 split 独立生成 UTC 模拟时段的查询事件，目标约 50,000 行且主场景约 95% 正常、5% DGA。D3 只能使用 D2 已冻结的域名池和划分，不得重新采样或跨集合移动域名；合法突发、低频 DGA 和词根拼接 DGA 的行为分布在 D3 设计中具体化。

D2 的标签只表示公开来源标签或已知生成方法。域名清单不是 DNS 解析记录；D3 生成的事件是模拟日志，不得描述为真实网络观测。
