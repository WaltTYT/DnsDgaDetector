# D3 DNS 查询日志生成设计

> 状态：评审通过
> 日期：2026-11-01
> 范围：阶段 1 的 D3；只生成离线合成查询日志，不执行 DNS 查询。
> 依据：[项目路线图](../specs/project-roadmap.md) 2.1、2.2、D3 检查点及[数据契约 v1](data-contracts.md)。

## 1. 目标与边界

D3 从 D2 冻结的 `data/splits.csv` 读取域名、标签、来源、手工算法和 split，为三个集合分别生成行为分布有重叠的合成查询事件，写入 `data/dns_log.csv`。本轮固定目标为 50,000 行，其中 47,500 行正常查询、2,500 行 DGA 查询；同一配置和输入必须逐字节可复现。

生成器只构造日志记录，不使用 dnspython 发起 DNS 请求，不连接递归解析器，不声称这些事件来自真实网络观测。真实 DNS 报文查询和解码属于路线图 D4。

D3 不改变 `splits.csv`、`dga_domains.csv`、D2 输入或五类数据契约，不做特征计算、基线拟合、阈值选择、LLM 判断或模型评估。

## 2. 输入、输出与共享契约

唯一数据输入为 `data/splits.csv`，其表头必须严格为：

```text
domain,label,source,algorithm,split
```

配置从仓库根目录 `config.json` 读取。沿用根级 `seed`、`window_seconds` 和 `paths.psl_snapshot`；生成器使用固定整数 seed、`window_seconds=60`、日志总行数、DGA 行比例及 D3 新增的模拟开始时间、客户端池和行为分布参数。可复现性以项目锁定的 Python 3.11.17 环境为准。D3 参数均为非敏感配置，不得把 API Key 写入配置。

实现计划需在 `config.json.log` 中采用以下默认值；这些是非敏感生成参数：

| 配置项 | 默认值 | 含义 |
|---|---:|---|
| `total_rows_approx` | `50000` | D3 精确事件总数，保留现有键名以避免无关配置迁移 |
| `dga_ratio` | `0.05` | DGA 事件占比 |
| `simulation_start_utc` | `2026-11-01T00:00:00.000Z` | train 时段起点，必须 UTC 整分钟 |
| `split_period_hours` | `24` | 每个 split 的独立时段长度 |
| `client_pool_size` | `100` | 从 RFC 5737 TEST-NET-1 生成的客户端数 |
| `active_client_fraction` | `0.20` | 较高负载客户端占比 |
| `active_event_fraction` | `0.50` | 较高负载客户端承载的事件比例 |
| `normal_behavior_ratio` | `routine: 0.80, burst: 0.20` | 正常事件内部场景比例 |
| `dga_behavior_ratio` | `high_frequency: 0.40, low_frequency: 0.35, word_digit: 0.25` | DGA 事件内部场景比例 |
| `mixed_window_fraction` | `0.20` | 每个 split 中与正常日常查询配对的高频 DGA 窗口比例；按向上取整计算 |
| `qtype_weights` | `A: 0.80, AAAA: 0.15, CNAME: 0.03, TXT: 0.01, NS: 0.01` | 各 `(split, label)` 池的查询类型权重 |

每个 `(split, label)` 的 qtype 数量按这些权重用最大余数法独立分配，固定顺序 `A`、`AAAA`、`CNAME`、`TXT`、`NS` 打破余数并列，确保类别间不会因随机波动形成系统性 qtype 偏差。正常行为权重、DGA 行为权重和 qtype 权重各自的比例和必须分别为 1（允许配置浮点表示误差 `1e-9`），否则配置校验失败。`mixed_window_fraction` 必须在 `(0, 1]`，以保证每个 split 都有混合窗口。

输出 `data/dns_log.csv` 严格采用契约 v1 表头和列序：

```text
event_id,timestamp,client_ip,qname,qtype,label,source,algorithm,split
```

遵循契约的数据类型及取值：`event_id` 从 1 连续递增；`timestamp` 为 UTC、毫秒精度、ISO 8601 且全文件单调不减；`client_ip` 为 IPv4；`qname` 使用 `splits.csv` 中规范化后的域名；`qtype` 仅取 `A`、`AAAA`、`CNAME`、`TXT`、`NS`；其余字段原样继承对应域名记录。只有 `source=manual_dga` 时 `algorithm` 可以为三种手工算法之一，其他来源必须为空。标签、来源、算法和 split 是评估元数据，不作为事件行为生成的可见证据，也不从事件内容中推断。

CSV 使用 UTF-8 无 BOM、LF 行尾及固定字段顺序。生成器先完成输入校验、配额计算和全部事件构造，再写同目录临时文件并原子替换目标；失败时保留已有 `dns_log.csv`。

## 3. 固定数量与 split 配额

`config.json.log.total_rows_approx` 在本设计的 D3 运行中作为精确目标行数使用；当前值 50,000。`dga_ratio=0.05` 对应精确的 2,500 条 DGA 事件，其余为 47,500 条正常事件。总 DGA 数按 `floor(total_rows * dga_ratio + 0.5)` 取最近整数（恰好半数时向上）；后续按 split 和行为分层的配额再使用最大余数法，并列按固定顺序 `train`、`val`、`test` 解决。`total_rows` 必须为正整数，`dga_ratio` 必须在 `[0, 1]`。非法或无法满足输入池约束的配置应报错，不静默改变目标规模。

先统计 D2 `splits.csv` 中各 split 的域名行数，按其比例为 50,000 条事件分配 split 总量；再按各 split 事件配额比例分配 2,500 条 DGA 事件。每个 split 的正常事件数是其总配额减去 DGA 配额。计算过程使用整数和最大余数法，确保各配额之和精确等于全局目标。

以当前 D2 划分（train 2,135、val 712、test 711 个域名）为例，事件目标分配如下；实现必须从输入动态计算，不得把该表硬编码：

| Split | 总事件 | 正常事件 | DGA 事件 |
|---|---:|---:|---:|
| train | 30,003 | 28,503 | 1,500 |
| val | 10,006 | 9,506 | 500 |
| test | 9,991 | 9,491 | 500 |
| **合计** | **50,000** | **47,500** | **2,500** |

目标池按 `(split, label)` 隔离。事件只能从同一 split、同一 label 的 D2 域名中抽取，允许同一个 `qname` 在多个事件及多个窗口重复出现，但绝不跨 split 移动域名或混合事件。D3 事件行数比例不代表唯一域名数比例；摘要需分别报告事件数、唯一 qname 数和聚合样本数。

## 4. 行为场景

事件先按固定 seed 派生的独立随机流分配到 split、客户端、行为类别、窗口、域名、查询类型和窗口内毫秒偏移。使用稳定摘要派生子 seed，不依赖 Python 进程随机化的 `hash()`，使某一类别的抽样变化不扰动其他类别。

各 split 使用相同的行为类别比例。类别配额通过最大余数法取整；余数并列时正常类别按 `routine`、`burst` 顺序，DGA 类别按 `high_frequency`、`low_frequency`、`word_digit` 顺序分配。每类内按固定 seed 可重复抽取域名和窗口。

| 标签 | 场景 | 默认事件比例 | 生成约束 |
|---|---|---:|---|
| 正常 | 日常访问 | 80% | 通常每个 `(client_ip, window_start, qname)` 有 1–2 次查询；常用 qname 可在不同窗口重复出现 |
| 正常 | 合法突发 | 20% | 在一个客户端分钟窗口中对同一 qname 聚集 3–12 次查询，允许形成较高频率或较短间隔 |
| DGA | 高频随机型 | 40% | 在一个客户端分钟窗口中对同一 qname 聚集 5–12 次查询 |
| DGA | 低频随机型 | 35% | 通常每个 `(client_ip, window_start, qname)` 有 1–2 次查询，将 qname 分散到不同窗口，避免所有 DGA 都呈高频特征 |
| DGA | 低熵词根型 | 25% | 事件域名从该 split 的 `word_digit` 手工 DGA 池选取；每个 `(client_ip, window_start, qname)` 有 1–4 次查询，覆盖稀疏与小规模重复访问 |

上述比例是模拟设计参数，不是现实网络测量结论。行为数量约束作用于同一 qname 的事件组；路线图中的频率特征 `F` 则按 `(client_ip, window_start)` 统计该窗口所有 qname 的查询总数，查询间隔 `I` 也按该客户端窗口内所有事件的时间戳计算。每个类别的事件总数 `n` 按其允许的组大小范围 `[min_size, max_size]` 拆分为 `ceil(n / max_size)` 个组，再用该类别的独立固定随机流，在保证每组大小均落在该范围且组大小总和为 `n` 的前提下确定各组大小：依次在可使剩余事件仍能由剩余组满足大小范围的可行整数区间内均匀抽取，最后一组取剩余值。`n=0` 时不建组，正数 `n` 无法满足最小组大小时配置校验失败。一个事件组内事件共用一个从对应 `(split, label)` 域名池抽取的 qname、一个客户端和一个分钟窗口；不同组可复用 qname，但默认不共用客户端分钟窗口，混合窗口配对除外。最大余数分配在当前配置下将 DGA 行分成每个 split 的高频/低频/词根型配额：train 600/525/375，val 和 test 各 200/175/125。每个 split 的 DGA 域名池必须覆盖所需场景；缺少 `word_digit` 域名时立即报错，不用其他算法或标签替代。正常突发组与 DGA 高频组的相邻查询间隔都从均匀分布的整数毫秒 `[1000, 5000]` 抽取。每组跨度不超过 55 秒，起始偏移在剩余窗口时间内确定性抽取。

默认情况下，不同事件组占用独立客户端分钟窗口；为覆盖路线图要求的混合客户端窗口，每个 split 按 `ceil(该 split 高频 DGA 事件组数 * mixed_window_fraction)` 选取高频 DGA 组，并为每组配对一个来自同 split 正常日常配额的单次查询。配对事件使用不同 qname、相同 `client_ip` 和 `window_start`，正常查询计入日常场景原有配额而非额外增加总行数；其与 DGA 查询共同参与窗口级 `F`、`I` 计算。配对窗口中的所有相邻事件间隔仍从 `[1000, 5000]` 毫秒内抽取，且整个事件序列跨度不超过 55 秒。未配对的其他事件组仍互不重叠。若默认混合比例无法在某 split 形成混合窗口，生成失败，不静默跳过。

行为类别必须有意重叠：正常合法突发可出现高频和短间隔；正常域名池包含外观复杂的难负样本；低频随机 DGA 可以具有正常的低查询频率；词根型 DGA 不强制同时满足高频规则。正常合法突发与 DGA 高频组共用每个 qname 5–12 次/窗口的重叠范围，并使用相同的窗口内间隔分布；正常日常访问与 DGA 低频组共用每个 qname 1–2 次/窗口的稀疏范围。混合窗口使正常样本也能继承同一客户端窗口内的高 `F` 和短 `I`，对应客户端级行为规则可能连带误报的检查点。测试从日志按 `(client_ip, window_start)` 重算真实特征，确认正常与 DGA 样本在低频和 5–12 次窗口总量均存在重叠；同时验证每个 split 均有混合标签窗口，并比较突发/高频组的相邻查询间隔，确认区间相交。不得设计成正常永远低频、DGA 永远高频，也不得令 `source`、`algorithm`、`label` 与唯一时间段或 `qtype` 形成可直接识别的泄漏信号。行为类别只在生成器内部和 JSON 摘要中使用，不新增数据契约字段。

客户端池使用配置定义的固定数量 IPv4 文档地址（默认 100 个，使用 RFC 5737 TEST-NET 地址，不使用本机或真实用户 IP）。默认配置让 20% 的客户端承载约 50% 事件，其余客户端承载其余事件；组内按固定 seed 抽样。该倾斜仅用于合成客户端负载差异，不代表真实用户分布。

`qtype` 以 `A` 为主，默认权重为 A 80%、AAAA 15%、CNAME 3%、TXT 1%、NS 1%。同一权重策略用于正常/DGA 及各行为场景；`qtype` 不参与 D3 标签分配，D5 主特征也不使用它。

## 5. 时间与事件排序

配置提供固定 UTC `simulation_start_utc`，且必须精确对齐整分钟。每个 split 使用由 `split_period_hours` 指定的独立且不重叠时段：train 从开始时间起，val 从开始时间加一个 `split_period_hours` 起，test 从开始时间加两个 `split_period_hours` 起。默认时长为 24 小时，因此默认偏移为 24/48 小时。每个时段按 UTC 整分钟对齐 60 秒窗口。该分段便于重现和审计，不表达真实日期上的训练/测试漂移；相同配置下三个 split 使用相同时间长度、行为和客户端分布。

事件时间戳落在所属窗口内部，以毫秒为精度。routine、low-frequency 和 word-digit 场景在窗口内使用较分散的偏移；burst/high-frequency 场景使用符合其场景的聚集偏移。生成完毕后按 `(timestamp, 稳定生成序号)` 稳定排序，再从 1 开始赋 `event_id`。同一毫秒可以有多个事件，排序仍由唯一递增的 `event_id` 确定。

任何事件的窗口起点按 UTC epoch 进行 60 秒非重叠对齐。该定义与路线图主评估键 `(client_ip, window_start, qname)` 一致；D3 本身不在日志里新增 `window_start` 列。

## 6. 输入校验、摘要与错误处理

生成前校验配置类型、精确 schema、域名唯一性、枚举值、标签与来源/算法语义、split 集合及各 `(split, label)` 样本池。对于必要的 eTLD+1 隔离检查，使用配置指定的本地 PSL 且禁用网络与缓存回退；同一 eTLD+1 出现在多个 split 时拒绝生成。不得重新规范化后悄悄改写 D2 输入。

命令行入口为 `python -m src.gen_log`，只从仓库根目录读取 `config.json`、`data/splits.csv` 和本地 PSL，只写 `data/dns_log.csv`。不发 DNS 查询、不访问数据集网站、不生成或修改其他 D2 文件。

成功时向 stdout 输出 JSON 运行摘要，不新增 summary 文件。至少包含配置 seed、输入和输出 SHA-256、目标与实际总行数、DGA/正常行数、每 split 和 label/source/qtype/内部行为类别的行数、混合标签客户端窗口数、唯一 qname 数、聚合键数量、各 split 时间范围，以及显式声明 `synthetic=true`。失败时以非零退出码报告输入、配额或输出错误；已有输出须保持不变。

## 7. 测试与验收

测试在 `tmp_path` 构造小型 `splits.csv`、配置及包含 PRIVATE 规则的本地 PSL；不依赖当前仓库真实域名数据、网络或外部 DNS。至少验证：

- 输出表头、列序、UTF-8 无 BOM、LF、行数、唯一 `event_id`、UTC 毫秒格式、时间单调不减和 qtype 枚举符合契约。
- 总事件数与 95/5 标签配额精确；最大余数法在 split/行为配额上的和正确，余数并列规则稳定。
- 每个事件的 `qname,label,source,algorithm,split` 与唯一 D2 输入记录一致，且无域名跨 split、标签冲突或 eTLD+1 泄漏。
- 每 split 的日常/合法突发/高频 DGA/低频 DGA/词根 DGA 行为配额符合设计；两类行为特征分布有重叠，不存在由 qtype 或时间段直接推导标签的规则。
- 每个 split 均有按配置比例生成的混合标签客户端窗口；窗口级 `F`、`I` 可从原始事件独立重算，正常查询与 DGA 查询共享客户端行为特征。
- 固定 seed、配置和输入连续运行两次，输出逐字节相同；独立 split 随机流不受其他 split 抽样顺序影响。
- 在测试中阻断 socket 网络连接后，端到端生成仍成功；生成期间不会读取 DNS 服务或联网获取 PSL。
- 错误配置、缺少 split 标签池、算法元数据错误、eTLD+1 跨 split 或写入失败时返回失败，sentinel `dns_log.csv` 不被部分覆盖；D2 其他产物保持不变。
- 摘要的总量、标签、split、qtype、唯一域名与聚合键计数可以从写出的日志独立复算。

D3 检查点：日志行、唯一域名和 `(client_ip, window_start, qname)` 聚合样本的数量及类别比例分别报告；时间戳可解析且排序正确；D2 域名划分无泄漏；日志明确标记为合成数据，不得称为真实查询记录。

## 8. 数据权利与交付限制

D3 不改变 D2 数据源的许可状态。当前 Mendeley 上游材料和派生样本的再分发权尚未独立确认；以这些域名生成的 `dns_log.csv` 仍是相关派生结果，许可确认或替换数据源并重跑 D2 前，只能在本机用于开发和验证，不得提交或公开分发。测试必须使用自建临时 fixture，避免把受限来源样本写入测试文件。

## 9. D3 完成边界

D3 完成意味着日志生成器可离线、确定性地读取 D2 划分并生成符合契约的合成查询日志；固定总量及标签比例正确；三类 DGA 与正常突发/日常访问行为均有覆盖及重叠；时间、元数据、摘要与原子替换检查通过。D3 不等于真实 DNS 网络实验完成，也不完成 D4 报文解码、D5 基线拟合或后续检测评估。
