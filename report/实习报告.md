# 实习报告：DNS异常查询检测的规则 + LLM混合方案

> 课程：网络技术综合实习（谢希仁《计算机网络》第 8 版，第 6 章 应用层）
> 团队分工：组员 A 数据与日志生成；组员 B 教材原理、特征与规则；组长 LLM 复核、评估与集成
> 代码与产物：DnsDgaDetector 仓库；报告日期：2026-11-24

## 摘要

本项目围绕 DNS 异常查询检测，完成“教材原理复现 + 规则引擎 + LLM 语义复核”的完整链路。数据侧使用公开榜单、公开 DGA 家族与三种手工构造算法，按可注册域分组划分训练、验证和测试集，并合成 50,000 行 DNS 查询日志；检测侧以 60 秒非重叠窗口聚合样本，基于域名熵 `H`、客户端频率 `F` 和查询间隔 `I` 拟合正常基线，规则结论为 `R = E OR B`；仅对 `E=1 且 B=0` 的样本调用 GLM-4-Flash 做三态语义复核，最终改判为 `hybrid = B OR (E AND verdict != normal)`。测试集上，聚合样本口径的 FPR 由 0.53% 降至 0.40%，精确率由 47.50% 升至 54.29%，召回率保持 13.87%；唯一域名口径的 FPR 由 1.18% 降至 1.01%，精确率由 69.57% 升至 72.73%。混合方案正确撤回 5 个误报、错误放行 0 个告警。结果显示 LLM 复核能小幅降低误报，但无法提升召回，整体召回偏低，结论应定位为教学验证而非真实部署能力。

**关键词**：DNS；DGA；规则引擎；大语言模型；误报率；可复现实验

## 一、教材原理复现

### 1.1 域名层级与公共后缀

域名从右向左分层。以 `www.example.co.uk` 为例，`uk` 是顶级域，`co.uk` 是公共后缀，`example.co.uk` 是可注册域（eTLD+1），`www` 是子域。检测只能在可注册域的“公共后缀左侧标签”上稳定计算词形特征，因此项目使用固定本地 Public Suffix List 快照解析公共后缀，再取 eTLD+1 的注册标签（如 `example`）计算熵。PSL 只用于后缀判定，不作为正常域名数据集；快照固定为 2026-11-06 版本，运行时不联网更新。

### 1.2 递归查询与迭代查询

教材第 6 章区分两类查询：主机向本地域名服务器的查询一般采用递归查询；本地域名服务器向根、顶级域和权威服务器的查询通常采用迭代查询。项目用 `dns.resolver.Resolver` 向配置的递归解析器（实测为 `114.114.114.114` 与本地网关 `192.168.1.1`、`192.168.3.1`）发送 RD=1 的递归请求，响应中 RA=1 表示服务器支持递归。

必须强调观测边界：脚本只看到 stub resolver 与递归解析器的一次交互，看不到递归解析器内部向根/TLD/权威服务器发起的迭代过程。报告不把一次 `Resolver` 调用描述为完整的逐级迭代演示，也不声称观测到了根服务器链路。

### 1.3 DNS 报文结构

DNS 报文由 12 字节首部和四个可变长区段组成。首部字段包括 ID、QR、Opcode、AA、TC、RD、RA、Z、RCODE 以及 QDCOUNT、ANCOUNT、NSCOUNT、ARCOUNT；区段依次为 Question、Answer、Authority、Additional。项目对每次查询逐字段解码，并把原始响应以 base64 一并保存，结构化记录见 `report/evidence/dns_demo_20261104.json`。

以 `www.baidu.com` 的实测响应为例：

| 字段 | 实测值 |
|---|---|
| 报文 ID | 18291 |
| QR / Opcode | response / QUERY |
| AA / TC / RD / RA | false / false / true / true |
| RCODE | NOERROR |
| Question | `www.baidu.com.`，TYPE=A，CLASS=IN |
| Answer | `www.baidu.com.` CNAME TTL=419 → `www.a.shifen.com.`；`www.a.shifen.com.` A TTL=304 → `183.2.172.177` |

该例同时展示了两点教材内容：一是 CNAME 链的存在，终端用户查询的域名并不直接持有 A 记录；二是 TTL 随缓存时间递减，419 秒与 304 秒的差异说明响应来自递归解析器缓存而非每次都回源。

### 1.4 记录类型、TTL 与缓存

项目演示覆盖 A、AAAA、CNAME、NS、TXT 与 SOA 等类型。A 记录给出 IPv4 地址，AAAA 给出 IPv6 地址，CNAME 给出别名目标，NS 指出区域权威服务器，SOA 提供区域管理信息，TXT 承载文本数据。TTL 决定记录在缓存中的存活时间，递归解析器在 TTL 内直接返回缓存结果，这也是同一域名多次查询延迟差异的主要来源之一。检测侧只使用查询名与查询时间，不使用响应内容，因此 TTL 与缓存行为属于原理复现内容，不进入特征。

### 1.5 NXDOMAIN 与 DGA 的关系

项目用 `this-domain-should-not-exist-xyz12345.example` 演示了 NXDOMAIN：响应 Answer 为空，RCODE 为 NXDOMAIN，Authority 节通常返回 SOA。DGA 域名常因未注册或已下线而大量返回 NXDOMAIN，但这不是必然规律，也存在 DGA 域名正常解析的例外。当前三特征方案没有把 NXDOMAIN 作为检测特征，这一点在结论中作为明确的范围边界说明，避免把“未实现”写成“已验证无效”。

### 1.6 复现证据与边界

证据文件 `report/evidence/dns_demo_20261124.json` 保存了 5 个正常域名与 1 个不存在域名的查询记录，包含查询耗时、nameserver、报文首部、Question/Answer/Authority/Additional 解码结果与原始响应 base64。同批查询的抓包材料一并归档：`report/evidence/dns_capture_20261124.pcapng` 为原始报文，`dns_capture_20261124_decode.txt` 为 6 个域名的逐字段解码文本，`dns_capture_20261124_wireshark.png` 为 Wireshark 过滤视图截图。

抓包环境与结果：在“以太网”接口、本机地址 172.22.148.204 上以 `udp port 53 or tcp port 53` 过滤，捕获 25 秒共 101 个包；6 个演示域名均出现查询与响应，解析器为 202.116.160.29（另有一次发往本地 192.168.202.110 的并行查询），`www.baidu.com` 的响应包含 CNAME 链 `www.a.shifen.com`，`this-domain-should-not-exist-xyz12345.example` 的响应 rcode=3（NXDOMAIN）。截图以 `dns.qry.name contains baidu` 过滤，列表给出两次查询与一次带 CNAME 的响应，详情面板展示查询包的以太网、IPv4、UDP 与 DNS 四层结构，可用于对照 1.2 的字段表。

边界说明：普通抓包只能看到本机可见链路上的明文 DNS，DoH/DoT 流量不在 `udp.port == 53` 的抓取范围内；本项目也没有向根服务器直接发起查询。教材原理复现的目标是“可验证、可解释”，不是复刻递归解析器的内部实现。

## 二、实验设置与 AI 增强

### 2.1 数据来源

| 来源 | 规模 | 说明 |
|---|---|---|
| 正常域名 | 3,000 条候选，2,888 条有效 | Mendeley Data 数据集（DOI `10.17632/nhvyvytn2h.1`）中 `family=legit` 子集，源自 Majestic Million，按原始顺序取前 3,000 个唯一域名 |
| 难负样本 | 100 条候选，95 条有效 | OpenDNS Top 10k 中的 CDN/云服务（20→15）、DGA-like 词形（20）、含数字合法域名（60），逐条记录来源 |
| 公开 DGA | 300 条候选，295 条有效 | 同一 Mendeley 数据集中的 DGArchive 家族，覆盖 158 个家族（上游共 160 个，抽样后命中 158 个），按固定 seed 分层配额抽取 |
| 手工 DGA | 300 条 | `rand_alpha`、`word_digit`、`md5_date` 三种算法各 100 条 |
| 公共后缀 | 固定快照 | PSL 2026-11-06 版本，MPL 2.0，SHA-256 前缀 `019fcc1d…` |

Mendeley 数据集页面标注 CC BY 4.0，但其上游 Majestic Million 与 DGArchive 材料的再分发权尚未独立确认，因此派生输入与含其样本的生成产物仅在本机保留，不随仓库公开。公开 DGA 标签仅表示数据提供方给出的已知生成类别，不构成对域名当前恶意性的独立验证。

### 2.2 数据划分

先规范化、去重并检查标签冲突，再按 eTLD+1 分组，以固定 seed `20261101` 按 60%/20%/20% 划分。13 条同时出现在正常榜单与难负清单的域名按“难负优先”归并，并在摘要中计数。最终 3,565 个注册域划分为：

| 集合 | 注册域数 | 正常 | 手工 DGA | 公开 DGA | 难负 |
|---|---:|---:|---:|---:|---:|
| train | 2,139 | 1,725 | 180 | 177 | 57 |
| val | 713 | 575 | 60 | 59 | 19 |
| test | 713 | 575 | 60 | 59 | 19 |

同一注册域及其子域不跨集合，三种手工算法在各集合均按 1/3 覆盖。划分文件为 `data/splits.csv`，SHA-256 记录在 `results/run_manifest.json`。

### 2.3 合成 DNS 查询日志

日志为固定 seed 合成的查询序列，不代表真实用户流量。三个集合使用独立模拟时段（UTC），共 50,000 行：train 30,000、val 10,000、test 10,000；行级标签为正常 47,500、DGA 2,500，比例 95%/5%。查询类型分布为 A 40,000、AAAA 7,500、CNAME 1,500、NS 500、TXT 500。

行为分布刻意保留重叠：正常侧包含日常访问 38,000 次与合法突发 9,500 次；DGA 侧包含高频随机 1,000 次、低频随机 875 次与低熵词根拼接 625 次。窗口中同时含正常与 DGA 查询的混合窗口共 18 个（train 10、val 4、test 4），用于检验客户端级行为规则的连带告警。

三个统计层次必须分开报告：

| 层次 | 数量 | 说明 |
|---|---:|---|
| 日志行 | 50,000 | 行级 DGA 占比 5% |
| 唯一完整域名 | 3,356 | 同一域名可多次查询 |
| 聚合样本 | 20,483 | `(client_ip, window_start, qname)`，val/test 各 4,098 |

聚合后 val/test 的阳性样本均为 137/4,098（3.34%），低于行级 5%，原因是高频 DGA 查询被折叠进同一样本。评估以聚合样本为主口径，另报唯一域名口径。

### 2.4 特征与正常基线

| 特征 | 计算口径 | 缺失处理 |
|---|---|---|
| 域名熵 `H` | 对 eTLD+1 的注册标签按字符计算 `H = -Σ p(c) log2 p(c)`，小写、保留连字符 | 无法提取注册域时单列，不静默赋零 |
| 客户端频率 `F` | 同客户端在 60 秒窗口内的全部查询次数，单位次/分钟，关联至窗口内每个域名样本 | 窗口必有值 |
| 客户端间隔 `I` | 同客户端窗口内相邻查询时间差的中位数，单位秒 | 少于 3 次查询记缺失，缺失不触发间隔规则 |

基线只用 train 中 `label=0` 的数据拟合：`H` 在唯一注册标签上取 P99，`F` 在纯正常客户端窗口上每窗口计一次取 P99，`I` 在有效窗口上取 P1。冻结值为：

| 特征 | 分位数 | 阈值 | 比较符 | 样本量 |
|---|---|---:|---|---:|
| `H` | P99 | 3.5466 | `>` | 1,699 个唯一标签 |
| `F` | P99 | 12.0 | `>` | 11,870 个窗口 |
| `I` | P1 | 1.751 | `<` | 475 个有效窗口（总窗口 11,870） |

基线分布与阈值位置见 `results/figures/baseline_histograms.png`。分位数采用 `numpy.percentile` 线性插值；`I` 的有效窗口仅占 4%，说明多数客户端窗口查询次数不足 3 次，间隔规则覆盖范围有限，报告不把它当作独立证据。

### 2.5 规则引擎

定义熵规则 `E = (H > 3.5466)`，行为规则 `B = (F > 12.0) OR (I < 1.751)`，纯规则结论 `R = E OR B`。三项都只是可疑线索：高熵可能来自合法短域名或哈希子域，高频可能来自合法突发，短间隔可能来自页面并发加载。客户端级频率与间隔规则还会连带标记同窗口的正常域名，这一点在结果分组中单独观察。

### 2.6 送审范围与提示工程

主方案只把 `E=1 且 B=0` 的聚合样本按规范化 qname 去重后送 LLM。行为告警 `B=1` 不被送审，原因是 LLM 只能看到词形，缺少否定行为证据所需的信息，若允许其放行会造成“语义正常即可洗白高频查询”的漏洞。

提示模板固定为 v1（`prompts/dga_judge_prompt.md`），只含两个变量：规范化域名 `qname` 与注册标签 `registrable_label`。模板要求返回单个 JSON 对象：

```json
{"verdict": "DGA|normal|uncertain", "reason": "不超过20字的依据"}
```

模板明确告知模型看不到查询频率、间隔、来源、真实标签与信誉数据，不得声称验证过注册信息或实时解析；同时给出“有语义不等于正常”“看着随机不等于 DGA”两条陷阱和 CDN 哈希子域示例。模板正文的 SHA-256 为 `c75112bd…`，改动正文必须升级版本并更新哈希，旧缓存随之失效。

### 2.7 改判规则与工程保障

| 样本情况 | 混合方案输出 |
|---|---|
| `R=0` | 正常，不请求 LLM |
| `B=1` | 保留告警，不由 LLM 放行 |
| `E=1, B=0`，verdict=`normal` | 撤回告警，保留原始规则证据 |
| `E=1, B=0`，verdict=`DGA` 或 `uncertain` | 保留告警 |
| 超时、重试耗尽、格式错误、缓存缺失 | 记 `uncertain` 并保留告警，失败原因单列 |

即 `hybrid = B OR (E AND verdict != normal)`。调用默认串行，超时与临时错误最多重试 3 次，认证与参数错误不重试；`temperature=0`，`max_tokens=32`。缓存键包含规范化输入、模型名、接口地址、模板哈希与生成参数，任一变化即失效。离线模式绝不请求网络，缓存缺失按 `uncertain` 降级，不伪造结论。评估代码自动断言 `FP_hybrid ⊆ FP_rule` 与 `TP_hybrid ⊆ TP_rule`，违反即报错，防止“降低误报”的结论靠报告自觉。

### 2.8 评估口径

主口径为聚合样本，两方案在完全相同的样本上计算 TP/FP/FN/TN；辅助口径为唯一完整域名，同一域名任一窗口告警即判检出。指标定义：

- `FPR = FP/(FP+TN)`
- `FNR = FN/(FN+TP)`
- `Precision = TP/(TP+FP)`
- `Recall = TP/(TP+FN)`

分母为零时输出 `N/A` 并给出支持样本数。由于样本不平衡，不以 accuracy 作为主结论；窗口内样本相关，不把 50,000 行日志当作独立证据宣称统计显著。

### 2.10 AI 增强的净效果

混合方案相对纯规则的净变化是：测试集聚合口径少 5 个 FP、多 0 个 FN，FPR 下降 0.13 个百分点，精确率上升 6.79 个百分点；唯一域名口径少 1 个 FP，FPR 下降 0.17 个百分点，精确率上升 3.16 个百分点。验证集方向一致，正确撤回 3 个、错误放行 0 个。

这一改善幅度不大，且召回率完全不变。原因是混合方案只允许 LLM 撤回熵规则告警，规则本体不变；能撤回的 FP 只有 `E=1 且 B=0` 的样本，测试集该类样本共 33 行、16 个唯一域名，可优化空间本身有限。因此结论应表述为“在规则告警边界内小幅降低误报”，而不是“AI 显著提升检测效果”。

## 三、AI 的局限性

### 3.1 结构上限：召回率不可能提升

由于送审集只包含 `E=1 且 B=0` 的样本，混合方案的阳性集合必然是纯规则阳性集合的子集。理论上 FPR 不会升高，但召回率也不会升高，FNR 可能上升。实测 test 的 FNR 在两方案下均为 86.13%，与这一推导一致。这是方法设计带来的上限，不是调参能解决的问题；要提升召回，必须改规则或增加新特征，而不是换更强的 LLM。

### 3.2 召回偏低与算法差异

测试集规则召回仅 13.87%（聚合口径）、20.78%（唯一域名口径）。分算法看，`rand_alpha` 为 27.8%，`word_digit` 为 2.1%，`md5_date` 为 0.0%。原因很直接：`md5_date` 生成 12–16 位十六进制串，字符集仅 16 个符号，短串的香农熵低于 `H=3.5466`，熵规则基本不命中；`word_digit` 由自然词根加数字组成，熵同样不高。LLM 无法补救这些样本，因为它们 `E=0`，不在送审范围内。

同时，测试集手工 DGA 召回 6.9%，明显低于验证集的 34.6%，而公开 DGA 在测试集召回 26.0%。这说明现有阈值在不同集合上的稳定性有限；样本量较小，不能据此推断某个算法“必然失效”，但足以说明当前特征对短随机串和词根型 DGA 不敏感。

### 3.3 不确定率偏高

| 集合 | DGA | normal | uncertain | 合计 | 不确定率 |
|---|---:|---:|---:|---:|---:|
| train | 19 | 2 | 29 | 50 | 58.0% |
| val | 14 | 1 | 6 | 21 | 28.6% |
| test | 9 | 1 | 6 | 16 | 37.5% |
| 合计 | 42 | 4 | 41 | 87 | 47.1% |

接近一半的送审域名被判为 `uncertain`，按改判表保留告警。这意味着大量本可撤回的误报没有被撤回，混合方案的 FPR 改善被限制在很小范围。模型倾向于“宁可不确定”是提示模板的显式要求，属于能力边界而非程序错误；但结果就是 AI 在这批数据上只兑现了很小一部分降误报潜力。

### 3.4 失败与错判案例

工程侧没有失败案例：96 次请求全部 HTTP 200，JSON 校验全部通过，无重试。能力侧的偏差全部表现为 `uncertain`，没有出现明确的 DGA/normal 反向判断，也没有把阳性样本误放行（错误放行 TP 为 0）。典型的保守判定是正常榜单中的高熵域名被判 `uncertain` 后继续告警，具体样本摘录见 `results/metrics.json` 的 `retained_uncertain_or_fail` 字段。

### 3.5 数据与标签边界

- 日志行为是合成的：正常突发、DGA 高频与低频分布按配置生成，不代表真实网络流量；合成标签只表示已知生成类别。
- 公开 DGA 标签来自第三方数据集，不构成对域名当前恶意性的独立验证；数据许可也限制了样本的公开再分发。
- 难负样本主要覆盖词法难例，其查询行为仍是正常客户端，未真正压到频率/间隔分支；验证集与测试集的难负样本误报均为 0，但这个 0 不能外推为“行为规则对难负样本安全”。
- 测试集阳性样本仅 137 个聚合样本、77 个唯一域名，分组后更少，指标波动大，不适合做显著性结论。

### 3.6 不能宣称的结论

本实验不能宣称：系统具备真实 DGA 检测能力；能泛化到未见家族；能实时检测；LLM 输出完全确定或可解释；或“混合方案整体优于纯规则”。可以成立的结论是：在给定冻结配置与合成日志上，语义复核在规则告警边界内小幅降低了误报，且未造成错误放行；同时暴露了规则对低熵 DGA 不敏感、LLM 不确定率高两项明确局限。

## 四、结论

1. 教材原理侧完成了可验证复现：真实 DNS 查询、报文逐字段解码、递归/迭代边界说明、NXDOMAIN 与 TTL 行为均有结构化证据。
2. 规则侧以三项可解释特征和训练集分位数建立基线，`R = E OR B` 的阈值与证据链可追溯，测试阶段未重新拟合。
3. AI 侧的价值被严格限定在“复核并撤回熵规则告警”：测试集撤回 5 个 FP、错放 0 个 TP，FPR 与精确率小幅改善，召回不变。
4. 主要局限是召回偏低与不确定率高：`md5_date` 与 `word_digit` 基本无法被熵规则捕获，47.1% 的送审域名被判 `uncertain`。
5. 全部指标可由 `results/metrics.json`、`results/features.csv` 与冻结配置离线复算，缓存覆盖 100%，满足可复现与断网演示要求。

### B. 三种 DGA 构造逻辑

| 算法 | 生成逻辑 | 参数 | 示例 |
|---|---|---|---|
| `rand_alpha` | 固定 seed 的随机数生成器产生 12–18 位小写字母 | `length`、`tld=.com` | `lpbvkecxozhjpdgh.com`、`pufwqzegwnghm.com` |
| `word_digit` | 从词根表抽 1–2 个词根，拼接 2–3 位数字 | `root_count`、`digit_count`、词根表哈希 | `download870.com`、`loginonline092.com` |
| `md5_date` | 对 `20261101|seed` 求 MD5，截取前 12–16 位十六进制 | `date`、`truncation_length` | `4a5a04aed162.com`、`2c1f3d9e7a10b.com` |

三种算法均为教学模拟，用于覆盖“随机字母、词根拼接、哈希截断”三类常见形态，不宣称复现任何真实恶意软件家族。每条样本的算法、seed 与参数记录在 `data/dga_domains.csv`，可逐条重建。

### C. 特征定义、基线与阈值

熵按字符频率计算，字符集为小写 ASCII 可打印字符并保留连字符；长度、数字比例与长度分组分布一并记录在 `results/baseline.json`。`F` 与 `I` 均在客户端窗口级统计且每窗口只计一次，避免高频域名重复加权。`I` 仅在窗口内查询次数不少于 3 时计算，缺失不触发规则；实测有效窗口 475/11,870，说明间隔规则覆盖面有限。

`results/baseline.json` 中的 `freeze_check` 为基线拟合阶段由生成器写入的占位标注，不参与运行时判断；权威冻结标记以 `results/run_manifest.json` 的 `freeze_check=frozen` 为准。

### D. 指标公式与手算验证

设 `TP=8, FP=2, FN=2, TN=18`，总样本 30：

- `FPR = 2/(2+18) = 10%`
- `FNR = 2/(2+8) = 20%`
- `Precision = 8/(8+2) = 80%`
- `Recall = 8/(8+2) = 80%`

该样例写入 `tests/test_evaluate.py` 作为手算基准，并覆盖全正常、全 DGA、无阳性预测三种零分母场景，输出 `N/A` 且附支持样本数。`tests/test_decisions.py` 覆盖改判表全部分支与 API 失败降级，`tests/test_features.py` 覆盖熵、PSL、窗口边界与缺失间隔。当前 `pytest tests/` 共 337 项通过。
